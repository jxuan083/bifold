# bifold

左邊原始碼，右邊成品。改完 ⌘S 直接寫回硬碟上的真實檔案——不做副本，所以不會有兩份來源分岔。

兩種用途，不重疊也不會同時用：

| 模式 | 用來做 | 右邊是 | 專屬功能 |
|---|---|---|---|
| **簡報**（`.html`） | 視覺型簡報——要顏色、要排版、要拖著調 | 頁面本身 | 選取模式、拖邊界改間距、拖屬性名調數值、匯出 PPTX |
| **論文**（`.tex`） | 文件型產出——論文、履歷 | Tectonic 編出的 PDF | 點 PDF 跳回原始碼、⌘E 跳頁、重新編譯 |

共用的部分：檔案樹、儲存、搜尋、復原/重做、頁碼導覽、內建終端機。

工具列會依模式只顯示用得到的功能，左上角的徽章標示目前模式，滑上去會列出該模式有什麼。

## 用法

```bash
npm install                       # pdfjs-dist / node-pty / ws / @xterm
node src/server.js 8790 /abs/path/to/deck.html
node src/server.js 8790 /abs/path/to/paper/main.tex
```

port 被佔用會自動往上找一個能用的，並在啟動訊息告訴你實際用了哪個。

每次都打完整路徑很煩的話，`npm link` 之後就能直接 `bifold <檔案>`：

```bash
cd /path/to/bifold && npm link
bifold ~/Desktop/deck.html
```

路徑可以直接貼 Finder 或瀏覽器複製來的 `file://` URL，中文被 percent-encode 成 `%E5%B7%A5%E4%BD%9C` 也吃得下。

啟動後開 http://127.0.0.1:8790。左上角 ☰ 開關檔案樹，點檔案就切過去。要換專案就按「開啟…」叫出 Finder，或直接貼絕對路徑。

選 Finder 而不是瀏覽器的 `<input type="file">`：後者拿不到絕對路徑（安全限制），而這個工具讀寫的是硬碟上的真實檔案。選資料夾時會自動找出裡面的主檔開啟。

檔案樹列出專案裡所有可編輯的檔案（`.tex` 專案含 `.bib` / `.sty` / `.cls`），主檔右邊標一個 ● ——編著 `sections/intro.tex` 時，實際編譯的是哪一份要一眼看得出來。

`.tex` 需要先裝引擎：

```bash
brew install tectonic
```

## HTML 模式

預覽是即時注入行號的副本，**原始檔完全不動**。每個開標籤會被掛上 `data-l`（原始行號）與 `data-i`（序號），`<style>` 區塊跳過不注入，否則 CSS 會被寫壞。

- **選取模式** — 點預覽上的元素，左邊跳到對應行並選取整行
- **拖邊界** — 滑鼠移到 margin / padding 邊界會變成調整游標，拖了就改，放開才寫回原始碼的 inline style。會吸附到同層兄弟的相同屬性，其次吸附到 4 的倍數，按住 Alt 停用吸附
- **雙擊改文字** — 在畫面上直接改文案，Enter 送出、Esc 取消。只對「沒有其他標籤包在裡面」的元素開放——裡面還有 `<b>` 的話，純文字替換會把那些標籤吃掉
- **屬性面板** — 拖屬性名稱左右滑動改數值，即時反映在預覽上
- **即時預覽** — 打字就看到變化。還沒存的內容送到 server 記憶體渲染，**硬碟上的檔案不動**，所以「改壞了還沒存、關掉就算了」這條退路還在。圖片字型照樣從真實目錄拿，預覽仍然是真的
- **⌘S** 寫回真實檔案
- **PPTX** — 任何 HTML 簡報都能出。專案裡有 `build-pptx.sh` 就走它自己的（那種通常還要嵌影片、挑輸出檔名），沒有就用內建的，輸出到同目錄的同名 `.pptx`

內建的建置是截圖式：Chrome headless 印成 PDF → `pdftoppm` 每頁 200 DPI → pptxgenjs 鋪滿 13.333×7.5 吋版面。**不做向量轉換**是有原因的：HTML 和 OOXML 的排版模型不同，PowerPoint 重排 CJK 會把標題硬拆行、疊字，修復成本高於重做。需要可編輯的版本時，正確答案是交付 `.html` 本身。

需要 `pdftoppm`（`brew install poppler`）和 Google Chrome。因為 Chrome 是用 `file://` 讀硬碟，建置前一定會先存檔。

`.tex` 沒有即時預覽：Tectonic 讀的是硬碟，而且 `\input` 是相對路徑，寫到別處整份都會失效——要即時就得真的自動存檔，那條退路就沒了。所以 `.tex` 仍是 ⌘S 存檔並重編。

選取模式不用 DevTools 慣例的 `⌘⇧C`——那個會被 Chrome 自己攔走，網頁收不到。

序號的數法在前後端必須完全一致，否則寫回會寫到錯的標籤上——這是 `server.js` 的 `injectMarkers` 和 `ui.html` 的 `tagStart` 共用同一組規則的原因。

## 快捷鍵

| 鍵 | 作用 |
|---|---|
| `⌘S` | 存回真實檔案（`.tex` 會順帶重編） |
| `⌘E` | 把左右對起來：簡報模式切選取模式，論文模式從游標跳到 PDF 對應頁 |
| `Esc` | 關搜尋；沒在搜尋就退出選取模式 |
| `⌘F` | 搜尋原始碼，`Enter` 找下一個、`⇧Enter` 上一個 |
| `⌘Z` / `⌘⇧Z` | 復原 / 重做 |
| `⌃\`` | 開關終端機 |

## 終端機

底部是真的一個 pty 跑你自己的 shell，不是模擬幾個指令——所以 `tectonic`、`git`、`claude` 這些原本就在用的東西全都直接能跑。工作目錄自動設在專案根。拖標題列可以調高度。

**多分頁**：`＋` 開新的 shell，每個分頁是獨立的 pty，工作目錄和環境變數互不影響。沒有 `⌘T` / `⌘W`——那兩個會被 Chrome 攔走，網頁收不到，所以只能用按鈕。

只綁 `127.0.0.1`。這條通道等同本機 shell 存取，不要對外開。


## LaTeX 模式

論文通常不是單一檔案。開啟 `sections/intro.tex` 時，bifold 會往上最多三層找出真正的主檔（含 `\documentclass` 的那個，或 `main.tex` / `paper.tex` / `thesis.tex` / `index.tex`），**編譯主檔而不是當前檔**，否則預覽會是一份沒有 preamble 的殘骸。標題列會顯示 `intro.tex → main.tex` 讓你知道實際編的是哪份。

編譯產物全部進 `.bifold/`，方便一行 gitignore。

**雙向同步**，兩邊都靠解析 SyncTeX：

- **點 PDF → 跳原始碼**（主要互動）。點到的那一行如果在別的檔案裡，會自動切過去。挑選規則是「包含這個點、而且面積最小的行級 box」——SyncTeX 的 box 是巢狀的，整頁的 vbox 也包含你點的位置，但它對應的行號沒有意義。點在行距等空白處時會吸到最近的一行；離所有文字超過一英寸就什麼都不做，那時候不動比亂跳好
- **游標 → PDF 捲動**。找不到精確的行會往最近的行退——游標常停在空行或註解上，硬要精確匹配會很常失敗，體感像壞掉

PDF 由 PDF.js 畫在 canvas 上，不是交給瀏覽器內建的 viewer。這是必要的：內建 viewer 拿不到點擊座標，反向同步就做不成。

**編譯錯誤**：TeX log 動輒上千行，全部丟出來等於沒給，所以只抓第一個 `!` 錯誤和它的 `l.123` 行號，完整 log 收在「完整 log」後面。

### 編譯速度

| 情境 | 實測 |
|---|---|
| 第一次跑（Tectonic 抓整套 package） | 3 分 25 秒 |
| 遇到沒抓過的 package 組合 | 約 31 秒 |
| cache 全熱 | **0.77 秒** |

第一次會久，之後就不會了。選 Tectonic 而不是 MacTeX 是因為它會自己抓缺的 package，不必手動 `tlmgr install` 追缺件；代價就是第一次那三分鐘。

### 大文件

只畫看得到的頁，其餘留等高佔位框，捲到才補、離開就把位圖釋放。55 頁的論文實測常駐 2–3 頁、約 14 MB；整份畫出來的話是 260 MB，而且會讓分頁無回應超過 45 秒。

## 語法高亮

疊層做的：textarea 文字透明、游標和選取保留，底下那層 `<pre>` 畫上色後的同一份內容，兩層的 font / padding / white-space / tab-size 逐項對齊。

**不換成 CodeMirror 是刻意的。** `gotoLine`、搜尋、拖曳寫回 inline style、跟隨游標算行號，全都依賴 textarea 的 `selectionStart` / `setSelectionRange`——換掉等於把編輯器重寫一遍。疊層只加視覺，既有行為一行都不用動。

tokenizer 自己寫，沒引 Prism：只需要 LaTeX、HTML、CSS 三種，沒必要為此拖進一個支援兩百種語言的套件。`<style>` 區塊會交給 CSS tokenizer——簡報的樣式往往佔掉整份檔案一大半，不上色等於只做一半。

實測 62KB 的簡報 tokenize 18ms、137KB 的 LaTeX 32ms，配合 90ms debounce 打字不會頓。超過 400KB 就不上色，寧可沒有也不要卡。

## 已知限制

選檔對話框走 `osascript`，只有 macOS 能用。


反向同步的精度受限於 SyncTeX 的粒度：整個段落標在 `\par` 的位置，所以點段落裡任何一句都會跳到該段最後一行。章節標題與獨立段落則是精準的。點擊後閃現的框就是實際命中的範圍——框住整段代表這段只能對到一行，不是點歪了。
